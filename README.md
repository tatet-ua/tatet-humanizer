# tatet-humanizer

Агентний скіл: український текст без ознак машинної генерації.

*An agent skill that strips machine-generation tells from Ukrainian text:
characters unavailable on a keyboard and sentence patterns typical of LLMs.
Derived from [blader/humanizer](https://github.com/blader/humanizer),
adapted for Ukrainian grammar and typography. Documentation is in
Ukrainian.*

Проблема проста. Модель ставить символи, яких немає на клавіатурі, і будує
речення за впізнаваними шаблонами. Читач цього не аналізує, але відчуває.
Для карток товару, листів клієнтам і статей це втрата довіри.

Скіл закриває три шари: символи (те, чого немає на клавіатурі), артефакти
(службова розмітка, що приїхала копіпастом із чату) і мову (звороти, які
модель вживає частіше за людину).

## Установлення

Скіл написаний у стандартному форматі Agent Skills, тому працює в будь-якому
харнесі, що його підтримує. Найпростіший спосіб для всіх:

```bash
npx skills add tatet-ua/tatet-humanizer --global
```

Перевірено: CLI розпізнає Codex, Cursor, Gemini CLI, OpenCode, Kimi Code CLI
та ще з десяток агентів і розкладає файли по їхніх теках сам. Claude Code
підключається симлінком.

У конкретний проєкт, а не глобально:

```bash
npx skills add tatet-ua/tatet-humanizer
```

Файли лягають у `.agents/skills/tatet-humanizer/`. Цей шлях читають
Antigravity, Codex і решта агентів, що дотримуються специфікації.

### Окремі харнеси

**Claude Code**, як плагін із маніфестами:

```
/plugin marketplace add tatet-ua/tatet-humanizer
```

**Antigravity**, глобально для всіх воркспейсів: покласти теку в
`~/.gemini/config/skills/tatet-humanizer/`.

**Вручну**, якщо CLI недоступний:

```bash
git clone https://github.com/tatet-ua/tatet-humanizer.git
mkdir -p <тека-скілів-вашого-агента>/tatet-humanizer
cp -r tatet-humanizer/SKILL.md tatet-humanizer/references <тека>/tatet-humanizer/
```

Теку `references/` копіювати обов'язково, інакше скіл не знайде довідники.

### Що працює не скрізь

Хук автоматичної перевірки (`claude-code/hooks/`) використовує подію
`PostToolUse`, яка є лише в Claude Code і Cline. В інших харнесах скіл
працює як набір правил: перевіряє сам агент, автоматичного контролю після
запису файлу немає.

Решта, тобто самі правила, довідники й механіка застосування, від харнеса
не залежить.

## Використання

Викликається як `/tatet-humanizer` або спрацьовує сам на запитах виду
«напиши статтю», «опис товару», «перепиши текст», «прибери ознаки ШІ».

**Символи.** Пишемо тільки тим, що є на клавіатурі. Без окремого режиму для
статей: автор статті теж набирає текст на клавіатурі, а типографіку ставить
верстальник на своєму етапі. Тире записуємо дефісом із пробілами, лапки
прямими.

**Робота.** `Генерація`: пишемо одразу правильно. `Переписування`: правимо
готовий текст циклом чернетка, аудит, фінал.

**Стиль не чіпаємо.** Довгі речення з підрядними, сполучники-переходи,
образність і приєднувальні конструкції не є ознаками машини. Скіл чистить
те, чого людина не пише ніколи, а не те, що йому не до смаку.

## Щоб діяло в конкретному проєкті

Скіл спрацьовує за тригерами, тому може не підхопитися, якщо задачу
сформульовано інакше. Для проєктів, де тексти пишуться регулярно, є пакет
[claude-code/](claude-code/INSTALL.md). Три рівні, кожен закриває свою
дірку:

| Рівень | Що робить | Чого не покриває |
|---|---|---|
| Розділ у файлі правил | діє в кожній сесії без виклику | може потонути в контексті довгої сесії |
| Скіл проєкту | повний довідник на вимогу | залежить від тригерів |
| Хук `PostToolUse` | після кожного запису перевіряє файл і повертає зауваження моделі | не бачить текст у відповідях чату |

Мінімум це перший рівень, п'ять хвилин. Третій єдиний працює механічно, а
не за домовленістю.

запису файлу. Усе, що специфічне для одного харнеса, лежить у теці
`claude-code/`; решта портативна.

## Співвідношення з blader/humanizer

Скіл є похідною роботою від [blader/humanizer](https://github.com/blader/humanizer):
33 мовні патерни й підхід до детекції взято звідти. Але три правила
оригіналу для української не годяться, бо писані під англійську:

| Правило оригіналу | Що з ним зроблено |
|---|---|
| §14 тире прибрати повністю | замінено: в українській тире обов'язкове за граматикою |
| §19 тільки прямі лапки | замінено: ялинки є нормою української типографіки |
| §26 знімати дефіс у предикативі | адаптовано: `по-перше`, `будь-який` дефіс не втрачають |

**Для англомовних текстів лишається `blader/humanizer`.** Наш скіл його не
замінює, а доповнює для української. Один і той самий текст через обидва не
ганяти: вони конфліктують на тире, лапках і дефісах.

## Чого цей скіл не робить

Чистий ASCII не рятує, якщо структура і мова лишилися машинними.
Типографіка це гігієна, а не зміст. Розділи про розмітку й мову важливіші
за розділи про символи.

Виняток один: артефакти копіпасту з чат-інтерфейсів. Там кожне входження є
прямим доказом, а не ознакою.

Ще одне. Ознаки слабшають з часом: розробники моделей реагують на скарги, і
довгого тире в нових версіях помітно менше. Один символ доказом не є.
Працює зв'язка: символ не з клавіатури, середовище без автозаміни й
однакове написання по всьому тексту.

## Розробка

```bash
node scripts/validate.mjs
```

Перевіряє frontmatter, збіг версій із маніфестами, наявність 33 міток
патернів, збіг таблиць довідника з константами хука, маркер
самовиключення в кожному документі. CI ганяє те саме на кожен push.

Контракт супроводу описано в [AGENTS.md](AGENTS.md).
