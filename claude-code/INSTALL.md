# Встановлення в проєкт

Три рівні. Кожен працює окремо, разом закривають різні дірки. Мінімум це
рівень 1, п'ять хвилин роботи.

## Рівень 1: правило в CLAUDE.md

Найпростіше і найдієвіше. Діє в кожній сесії цього проєкту без нагадувань.

Скопіюйте розділ із [CLAUDE.snippet.md](CLAUDE.snippet.md) у кінець
`CLAUDE.md` вашого проєкту. Все.

Обмеження: правило можна проґавити посеред довгої сесії, коли контекст
заповнений іншим.

## Рівень 2: скіл проєкту

Дає повний довідник на вимогу, не займаючи контекст постійно.

    mkdir -p .claude/skills/tatet-humanizer
    cp ../tatet-humanizer/SKILL.md .claude/skills/tatet-humanizer/
    cp -r ../tatet-humanizer/references .claude/skills/tatet-humanizer/

Теку `references/` копіювати обов'язково, інакше скіл не знайде довідники.

Викликається як `/tatet-humanizer` або спрацьовує сам на запитах виду
"напиши статтю", "опис товару", "перепиши текст".

Якщо скіл уже стоїть глобально в `~/.claude/skills/`, цей крок пропустіть.

## Рівень 3: хук перевірки

Єдиний рівень, який працює механічно, а не за домовленістю. Після кожного
запису файлу перевіряє результат і повертає зауваження моделі, щоб та
виправила сама.

1. Скопіюйте скрипт:

       mkdir -p .claude/hooks
       cp ../tatet-humanizer/claude-code/hooks/check-text.mjs .claude/hooks/

2. Додайте вміст [settings.snippet.json](settings.snippet.json) у
   `.claude/settings.json` проєкту. Якщо файл уже існує, **злийте** розділ
   `hooks` з наявним, не переписуйте цілком: зламаний JSON тихо вимикає всі
   налаштування з цього файлу.

3. Перевірте, що конфіг валідний. Зламаний JSON тихо вимикає всі
   налаштування з файлу, тому крок не пропускайте:

       node -e "const s=require('./.claude/settings.json');const h=(s.hooks?.PostToolUse||[]).find(x=>x.matcher==='Write|Edit');console.log(h?'OK: '+h.hooks[0].command:'НЕ ЗНАЙДЕНО')"

   Має надрукувати `OK: node .claude/hooks/check-text.mjs`. Якщо впало з
   помилкою, у файлі битий JSON. Якщо надрукувало `НЕ ЗНАЙДЕНО`, блок
   `hooks` потрапив не туди.

   Якщо у вас є `jq`, те саме коротше:

       jq -e '.hooks.PostToolUse[] | select(.matcher == "Write|Edit")' .claude/settings.json

4. Хук почне діяти після перезапуску Claude Code або після відкриття меню
   `/hooks` один раз. Наглядач за налаштуваннями стежить лише за теками, в
   яких файл налаштувань був на старті сесії.

### Перевірка вручну

    echo '{"tool_name":"Write","tool_input":{"file_path":"тест.md"}}' | node .claude/hooks/check-text.mjs

На брудному файлі поверне JSON із переліком знайденого. На чистому не
поверне нічого.

### Налаштування

Змінні оточення в тому ж `.claude/settings.json`, розділ `env`:

| Змінна | Типово | Що робить |
|---|---|---|
| `TH_EXT` | `md,txt,html,htm` | Які розширення перевіряти |
| `TH_QUIET` | не задано | `1` прибирає повідомлення в інтерфейсі, модель зауваження все одно отримує |

Приклад для проєкту, де перевіряти треба ще й шаблони:

    {
      "env": { "TH_EXT": "md,txt,html,vue" }
    }

### Що хук не робить

- Не блокує запис. Модель бачить зауваження і виправляє сама.
- Не чіпає код: перевіряються лише розширення зі списку, а `node_modules`,
  `.git`, `dist`, `build` і `vendor` пропускаються завжди.
- Не спрацьовує на файлах, які самі описують ознаки ШІ: якщо в тексті є
  згадка tatet-humanizer, plain-text-output або Signs of AI writing, файл
  пропускається. Інакше документація про спецсимволи вічно сварилася б сама
  на себе.
- Не бачить тексту, який модель пише прямо у відповіді чату. Це закриває
  рівень 1.

## Що куди

| Рівень | Файл у проєкті | Комітити |
|---|---|---|
| 1 | `CLAUDE.md` | так |
| 2 | `.claude/skills/tatet-humanizer/` разом із `references/` | так |
| 3 | `.claude/hooks/check-text.mjs` | так |
| 3 | `.claude/settings.json` | так, це командні налаштування |

Якщо хочете увімкнути хук лише для себе, кладіть налаштування в
`.claude/settings.local.json` і додайте його до `.gitignore`.
