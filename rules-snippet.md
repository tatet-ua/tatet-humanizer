# Фрагмент для файлу правил проєкту

Скопіюйте розділ нижче у файл постійних правил вашого агента. Він діє на
кожну сесію в цьому проєкті, без викликів і без нагадувань.

Куди саме класти, залежить від харнеса:

| Харнес | Файл |
|---|---|
| Claude Code | `CLAUDE.md` |
| Antigravity, Codex та інші зі спільним форматом | `AGENTS.md` |
| Cursor | `.cursor/rules/` або `.cursorrules` |
| Windsurf | `.windsurfrules` |
| Gemini CLI | `GEMINI.md` або `AGENTS.md` |

Якщо ваш агент читає `AGENTS.md`, кладіть туди: це кросплатформенний файл,
і його розуміє більшість сучасних харнесів.

Правило й хук закривають різні дірки. Хук ловить те, що вже записано на
диск, але існує лише в Claude Code і Cline. Правило не дає проблемі
виникнути й працює скрізь, проте його можна проґавити посеред довгої
сесії.

## Текст без ознак машинної генерації

Коли пишеш будь-який текст для людей (документація, описи, листи, картки
товару, README, коміт-меседжі), використовуй тільки символи, які є на
українській клавіатурі.

**Апостроф.** Тільки прямий `'`. Слова п'ять, об'єкт, здоров'я, комп'ютер
пиши саме так. Похилий U+2019 заборонений: він з'являється лише з
автозаміни і видає машину.

**Лапки.** Тільки прямі `"`. Англійська пара U+201C та U+201D заборонена в
українському тексті. Вкладеність другого рівня не дотримуй: перебудуй
фразу.

**Тире.** Дефіс із пробілами: `Київ - столиця України`. Довге тире не
вживай. Ніколи не став тире як розрив думки посеред фрази, замість цього
дужки або коми.

**Заборонено також.** Три крапки одним символом (пиши три окремі), стрілки
(пиши `->` або словами), знак множення (пиши `x` або "на"), нерозривні й
вузькі пробіли, символи нульової ширини, емодзі будь-які, галочки,
псевдографіку для схем.

**Не чіпай** символи всередині блоків коду, шляхів, URL, регулярних
виразів і цитованих даних. Там юнікод буває значущим.

**Розмітка.** Не оформлюй пункти списку серією `**Термін:** опис`. Не пиши
Заголовки З Великої Літери Кожного Слова. Не роби таблицю там, де вистачає
двох речень. У листах, картках товару і повідомленнях розмітки не має бути
взагалі.

**Мова.** Не збивай переліки у трійки. Не додавай дієприслівникові хвости
(підкреслюючи, забезпечуючи, відображаючи). Не роздувай значущість
(ключова роль, знаковий момент). Не пиши "це не просто X, це Y". Не
завершуй загальним позитивом про майбутнє. Замість "слугує", "являє собою"
пиши просто "це". Не анонсуй те, що зараз зробиш (розгляньмо детальніше,
ось що треба знати) - просто роби. Не відкривай удавано відвертим зачином
(чесно?, ось у чому річ). Не перетворюй звичайні тези на афоризми (X це
мова Y). Не громадь короткі рубані фрази заради драми. Активні конструкції
замість пасивних: дослідники виявили, а не було виявлено. Довжина речень
має різнитися.

**Документація.** Описуй предмет, а не те, що змінилося. "Функція шукає за
хеш-таблицею", а не "цю функцію додано замість попереднього підходу".
Виняток - чейнджлоги й нотатки релізу, вони версійні за призначенням.

**Не вигадуй фактів.** Жодного імені, числа, дати чи посилання, яких немає
в джерелі. Якщо даних бракує, напиши, що їх немає, або прибери речення.

**Артефакти копіпасту.** Ніколи не лишай у тексті службову розмітку
чат-інтерфейсів: `:contentReference`, `oai_citation`, `utm_source=chatgpt`,
`【N†source】`, `[cite_start]`, дати-заглушки `2026-XX-XX`. Одне входження
робить походження тексту очевидним.

Повний довідник: скіл `tatet-humanizer`, файли `SKILL.md` і `references/`.
Для англомовних текстів ці правила не застосовуй, там працює
`blader/humanizer`.

## Якщо у проєкті вже є CLAUDE.md

Додавайте розділ у кінець, не переписуйте наявний файл. Якщо в проєкті вже
описано стиль текстів, поставте цей розділ поруч і зніміть суперечності
вручну: два правила про одне й те саме плутають більше, ніж жодного.
