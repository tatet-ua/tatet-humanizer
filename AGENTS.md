# AGENTS.md

Настанови для ШІ-агентів (Claude Code, Codex, Warp тощо), які працюють у
цьому репозиторії.

## Що це за репозиторій

Портативний скіл, реалізований markdown-файлами. Робочий артефакт це
`SKILL.md`: агент читає його YAML-frontmatter і далі текст правил. Кроку
збірки немає.

Скіл написаний у стандартному форматі Agent Skills, тому працює в будь-якому
харнесі, що його підтримує: Claude Code, Codex, Cursor, Antigravity, Gemini
CLI та інші. Перевірено через `npx skills add`, який розкладає файли по
теках цих агентів сам.

Специфічним для одного харнеса лишається тільки хук у `claude-code/`: подія
`PostToolUse` є в Claude Code і Cline, деінде її немає. Правила, довідники
й механіка застосування від харнеса не залежать.

Окремих інструментів для людей (консольних скриптів, браузерних чекерів) у
проєкті немає і не планується: перевірку виконує сам агент за правилами
скіла.

## Ключові файли

- `SKILL.md` - сам скіл. Frontmatter (`name`, `description`, `license`,
  `metadata.version`) і правила. **Джерело правди.**
- `references/symbols.md` - таблиці символів, коди, HTML-сутності, команди.
- `references/patterns.md` - 33 мовні патерни з мітками `[hNN]`.
- `rules-snippet.md` - розділ для файлу правил проєкту (`CLAUDE.md`,
  `AGENTS.md`, `.cursorrules` тощо). Портативний.
- `claude-code/` - специфічне для Claude Code і Cline: хук
  `check-text.mjs`, фрагмент налаштувань, інструкція.
- `README.md` - для людей: установлення, структура, співвідношення з
  blader/humanizer.
- `.claude-plugin/plugin.json` і `marketplace.json` - маніфести плагіна.
- `scripts/validate.mjs` - перевірки узгодженості, запускати перед
  публікацією.

## Контракт супроводу

### Мітки патернів

`references/patterns.md` містить **33 мітки** `[h1]`-`[h33]`, які
відповідають нумерації [blader/humanizer](https://github.com/blader/humanizer).
Вони потрібні для звірки при оновленні upstream.

Якщо додаєте власний патерн поза нумерацією blader, давайте йому мітку
`[t1]`, `[t2]` і так далі. Не переприсвоюйте `[hNN]`: нумерація має
лишатися звіряною з upstream.

Три мітки помічені як замінені або адаптовані: `[h14]` тире, `[h19]`
лапки, `[h26]` дефіси. Це навмисно, бо оригінальні правила писані під
англійську і в українській ламають граматику. Не «виправляйте» їх назад.

### Версія

Версія зберігається у двох місцях і має збігатися:

- `SKILL.md`, поле `metadata.version`
- `.claude-plugin/plugin.json`, поле `version`

Піднімати разом. Верхньорівневий ключ `version` у frontmatter скіла не
ставити: він не портативний між харнесами.

### Довідник і хук мають збігатися

Заборонені символи задекларовані двічі: у таблицях
`references/symbols.md` і в константах `claude-code/hooks/check-text.mjs`
(`HARD`, `INVISIBLE`, `ALWAYS`).

**Додаєте символ у таблицю - додайте в хук.** Інакше документація
обіцятиме перевірку, якої немає. `scripts/validate.mjs` звіряє це
автоматично: бере коди `U+XXXX` з розділів «Заборонено завжди» і
«Типографські, яких теж немає на клавіатурі» та перевіряє, що хук їх ловить.

Пам'ятайте про діапазони: `☀-➿` покриває сотні символів одним
записом, тому не кожен новий код потребує окремого додавання.

### Маркер самовиключення

Хук `claude-code/hooks/check-text.mjs` пропускає файли, у яких є рядок
`tatet-humanizer`, `plain-text-output` або `Signs of AI writing`. Це
потрібно, бо документація про ознаки ШІ навмисно містить приклади «як не
треба».

Створюючи новий markdown-файл у цьому репозиторії з прикладами
заборонених символів, згадайте `tatet-humanizer` у шапці. Інакше хук
сваритиметься на власну документацію.

### Перед публікацією

    node scripts/validate.mjs

Перевіряє: наявність файлів, frontmatter, збіг імені й версії з
маніфестами, 33 мітки, збіг довідника з хуком, маркер самовиключення в
кожному документі, резолвність посилань на `references/`.

## Редагування SKILL.md

- Зберігати коректний YAML-frontmatter.
- Текст під frontmatter це продукт. Правити як інструкцію для людини, а не
  як код.
- Тримати `SKILL.md` компактним. Деталі й приклади йдуть у `references/`:
  скіл вантажиться щоразу, довідники читаються за потреби.
- Мова репозиторію українська. Приклади писати українською: дослівний
  переклад англійських прикладів дає кальку, тобто саме те, проти чого
  правила.

## Чого не робити

- Не гнати текст цього репозиторію через сам скіл або через
  `blader/humanizer`: приклади «як не треба» тут навмисні.
- Не переносити з upstream правила `[h14]`, `[h19]`, `[h26]` у
  первісному вигляді.
- Не додавати залежностей: скрипти мають лишатися такими, що
  запускаються без установлення пакетів.
- Не заводити окремих інструментів для людей. Консольні утиліти, браузерні
  чекери й документи для розсилки в цьому проєкті були і свідомо прибрані:
  перевірку робить сам агент за правилами скіла.
- Не прив'язувати правила до одного харнеса. Усе, що специфічне для Claude
  Code, живе в теці `claude-code/`. SKILL.md і `references/` мають лишатися
  портативними.
